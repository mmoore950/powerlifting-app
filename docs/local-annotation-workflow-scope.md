# Local manual hub annotation: bounded scope

October 8, 2026. The human offered their own training videos and asked to do labeling themselves. A private folder has not been supplied; none has been read. This is an implementation proposal, not a working labeling tool or model-training result. Existing public development media remains local/ignored and the reference manifest remains empty.

## Recommended first workflow

Reuse **VGG Image Annotator (VIA) 2.0.12** for local point labeling, with a small project-specific frame-bundle preparer and strict JSON-to-reference adapter. The user opens a reviewed offline HTML file, loads predecoded images, clicks the near-side hub, selects visibility/uncertainty and saves the project/export locally. No video upload or account is needed.

Primary [VGG project documentation](https://www.robots.ox.ac.uk/~vgg/software/via/) describes standalone image tools and a BSD 2-Clause license. [Point-drawing guide](https://www.robots.ox.ac.uk/~vgg/software/via/docs/drawing_regions.html) and [attribute guide](https://www.robots.ox.ac.uk/~vgg/software/via/docs/creating_annotations.html) cover the required interaction. [Source license page](https://gitlab.com/vgg/via-suite/via/-/blob/master/LICENSE) identifies BSD 2-Clause; the downloaded HTML contains the full notice.

Actual source inspection: official [VIA 2 HTML](https://www.robots.ox.ac.uk/~vgg/software/via/via.html), 424,268 bytes, SHA-256 `a225d22d89fd5b901769670fb94d4e117543d748c1c2dd8cf2fa7a4777f08322`, retained under ignored `artifacts/annotation-scope`. It has local image import, point regions with original-image integer `cx/cy`, file/region attributes, local JSON/CSV export and project save/load. The point source rounds to original image pixels, so uncertainty must reflect at least its finite annotation resolution. The hosted HTML also includes Google Analytics injection; **do not launch that unchanged file with private images**. A reviewed derivative should remove analytics, retain the license and record the change/hash. Disable remote image/project paths and enforce a no-network content policy in the local variant. Verify that the actual labeling/export path makes no requests before private use. No VIA code executed or integrated in this scope checkpoint.

A custom canvas UI is a fallback only if a small real round-trip proves VIA's file-level visibility/corrections confusing; no need to rebuild generic point editing before that evidence.

## Timing and geometry must match the actual app

Current production source uses **AVAssetImageGenerator**, preferred-track transform, clean aperture, a **1024×1024 maximumSize**, zero requested tolerances and about **15 requests/second** via `VideoSampleClock`. Accepted observations use returned `actualTime`; duplicate/out-of-range frames can be skipped. It is not an AVAssetReader loop over all 30-fps source frames.

The Windows inspection inventories every source frame. Those inventories are useful media facts, but neither equal the app's accepted sample set nor prove matching clean-aperture/scaled image geometry. For example, the 1280×720 Commons frames will be size-limited in the app; the exact returned CGImage dimensions must be measured. Native export explicitly rejects reference/prediction geometry mismatch.

Prefer a bundle from the **same actual native returned images/times** selected for prediction. If a Windows PyAV preparer is used first, mark decoder/transform provenance and retain full PTS inventory; only label actual decoded frames. Later intersect with exact native returned rational times and verify upright geometry/content. Never interpolate timestamps, derive them from nominal FPS, or silently scale references to force a match. If native/PyAV image geometry differs, prepare an authoritative native bundle or explicitly validated geometry transform before scoring.

Each bundle needs immutable sidecar entries: frame ID/local image filename/image digest, exact media digest and relative path, decoder/version, actual timestamp `{value: decimal string, timescale: integer, epoch: integer}`, upright image width/height, applied transform/aperture/scale, source group, lift, intended semantic target and partition. Ordinal frame number is a navigation key, not time. Convert a decoder time base `a/b` with PTS `p` to rational `p*a/b` without floating conversion; reject unsupported range/epoch rather than guessing. Native epoch and actual CMTime are authoritative when provided.

## User steps and reference adapter

1. User selects the authorized local video folder/individual clips, identifies lift/source group and records permission for local evaluation. Initial provided clips can be development material. Choose an independent held-out group before tuning; exports/crops from one subject/session stay together.
2. Preparer creates a bounded local frame bundle and preconfigured VIA project. Show decoded timestamp/clip and target instructions; no reference labels prefilled. Select useful frames across movement and occlusion transitions; include actual prediction frames once native export exists.
3. For a **visible** target, click one near-side hub and supply uncertainty radius in upright display pixels. Correct a point by editing/moving it, or delete/recreate it. Select **occluded**, **outside-frame** or **uncertain** when appropriate and remove any point. Never click the far plate to substitute for an invisible near hub.
4. Save/reopen the local VIA project as a recovery file; export VIA JSON. Adapter joins frame IDs to the immutable bundle sidecar, not editable timestamp text in the UI. It normalizes original-image pixel points by verified upright width/height and emits `manual-reference` with the original exact timestamp.
5. Run existing formal/semantic reference validation and actual-media hash checks. Produce a completion/missing-label summary. Unreviewed frames stay unannotated; an empty/unreviewed frame is not automatically occluded or uncertain. Preserve previous exports until a new validated export succeeds.

File attributes: explicit visibility (initially unset), uncertaintyPixels (no default), review status. Clip target identity lives in the bundle. Visible references require exactly one finite in-bounds point and finite nonnegative uncertainty; non-visible references require no point and export null coordinates/uncertainty. Ambiguous multiple points, foreign frame IDs, changed image/media hashes, non-point shapes, invalid visibility/uncertainty, duplicate PTS, inconsistent geometry and source-group split leakage fail rather than silently repair. Unknown editable labels cannot overwrite sidecar metadata.

Export unchanged [reference schema](video-evaluation.schema.json): clip metadata includes `sourceGroup`, `sha256`, `localPath`, `split`, `synthetic:false`, `permissionEvidence`, `lift`, `targetID`, `uprightWidth/Height`. Every real annotation has `provenance:manual-reference`; synthetic UI verification remains separately labeled. Reference JSON and selected media stay under an explicitly authorized private root or ignored artifacts. Predictions remain separate. No model fitting is required to create these references; tuning/model selection comes later and must preserve held-out evidence.

## Smallest implementation and meaningful acceptance

First bounded milestone: local VIA variant with a pinned source/license and no-network behavior; frame-bundle/attribute project generator for the four approved development assets; strict VIA JSON adapter invoking existing validator; short user guide and local round-trip demo. No private corpus scan, automatic annotations, native detector changes, CI media publication, hosting or accounts. Use explicit paths, bounded frame count/storage, and original media/derivative identity; no package install beyond the already approved isolated tools.

Verify with a tiny clearly synthetic fixture: point click at non-default browser zoom round-trips to correct original pixels/normalized coordinates; visible→occluded correction removes the point; save/reload preserves labels; same exact rational timestamps above JS safe integer range remain strings; missing/foreign/duplicate/multiple-point/hash/partition cases fail. A browser network check must cover actual local import/edit/save/export. Then use a few actual public-asset frames for manual usability inspection without inventing ground truth or scoring accuracy. Native frame/preferred-transform/clean-aperture parity requires its own actual Apple check.

Provisional implementation checkpoint **30–50 minutes after leader acceptance**, no hard deadline, uncertainty around VIA import/export and local browser file behavior. Native exact-frame bundle scope needs actual Apple execution and a separate estimate once the seam and access are selected. Human annotation effort cannot be reliably estimated before the user's clip count/quality and a small labeling trial; estimate after roughly 20 actual labels. Full accuracy/release ETA remains unavailable until representative media, native predictions, device and hosting gates exist. This scope report is the authorized 5–10-minute research result; implementation requires the leader's next concrete dispatch.
