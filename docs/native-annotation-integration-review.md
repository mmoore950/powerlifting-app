## Concrete open steps

1. **Apple execution and real native-to-adapter round trip.** Four new app-host methods are source only. They inspect actual generated output if run, including PNG/ledger/prediction identity, but Windows Node tests use hand-built synthetic contracts and PNG headers. No test has yet fed an actual Apple-produced bundle through the Node CLI or browser. First compile/capture diagnostics are the next decision; an additional native-to-CLI/browser check can be scoped from that result without private media.
2. **End-user capture entry point and Apple access.** The helper is internal; there is no installed capture screen or standalone native command. Guide variables come from an explicit developer harness/registry. The user has no Mac, and no private folder has been supplied. The guide describes an available source seam, not a presently executable private-video contribution workflow. Selecting an authorized local Apple route remains a prerequisite; uploading private clips to CI is not a workaround.
3. **Source retention/portable handoff.** Completed directories contain images/JSON, not the movie. Clearing/removing the imported clip deletes its managed copy. The CLI still needs bytes at the recorded relative path. Preserve that copy before removal, or copy the unchanged original into a separate local asset root under the recorded relative filename and verify its hash. A bundle alone cannot satisfy media verification; no media-packaging feature was added.
4. **Full reps and reference registry.** Initial1s/16frame bounds deliberately cover a short window, not whole-rep performance. Repeated windows need distinct clip IDs, absolute original timestamps and the same recording/subject/session group and split. The adapter emits one clip and checks an explicitly supplied existing manifest; it does not merge/build a project-wide registry. A full-rep/window aggregation/registry workflow needs a later bounded decision. Do not claim complete motion/subject coverage from this source checkpoint.
5. **Build provenance and manual mode.** Decoder version is the actual OS string. Toolchain/Git revision are not automatically populated; caller modelID and retained runner/build metadata must identify the tested detector. Native test source exercises automatic capture, not a new manual-Vision capture runtime case. Existing manual-mode guards/export checks remain, but manual native execution has no new passing evidence.
6. **Provenance does not travel inside the reference schema.** The adapter's companion report records producer/session/prediction association. The unchanged scorer does not load that report or independently enforce a native-producer gate, so passing a renamed PyAV draft directly to the scorer remains possible. Supported evaluation retains the successful adapter report and exact associated prediction file. Scoring diagnostics are separate from native authenticity, representative accuracy and release acceptance; accuracyGatePassed remains false.
7. **Browser privacy/usability gate.** Native import, corrected visible-to-occluded save/reload/export, actual request observation and file-URL behavior remain pending after the prior IAB stall. Source checks cannot close this gate. No private use should begin before it passes, and no repeated stalled CUA operations were performed in this review.
